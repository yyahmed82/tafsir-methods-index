# قائمة التحقق التفصيلية لمراجعة طلبات السحب (PR Review Checklist)

دليل المراجع المستقل لفحص طلبات السحب في مستودع «فهرس مناهج التفسير» وإصدار الحكم الحاسم (`PASS` أو `BLOCK`).

---

## ١. استقلالية المراجعة والعدائية البناءة
- **شركتان مختلفتان**: المنفّذ والمراجع من شركتين وموديلين مختلفين (مثال: المنفذ Claude Code والمراجع Codex/Antigravity، أو العكس).
- **مراجعة عمياء عدائية**: المراجع لا يفترض صحة الكود ولا يقبل تأكيدات المنفذ؛ بل يختبر الحدود القصوى وحالات الحافة.
- **التسجيل**: توثيق هوية الوكيل المنفذ والوكيل المراجع واسم النموذج الفعلي دون أي أسماء أشخاص.

---

## ٢. سلامة وثبات البيانات (Data Immutability Gate)
يُمنع منعاً باتاً تعديل أو إضافة أو حذف أي ملف في المسارات المثبتة:
- `data/raw/`, `data/**/raw/`
- `data/**/layers/`
- `data/**/spans/`
- `data/**/windows/`

**أمر التحقق الإلزامي**:
```bash
git diff origin/main -- data/
```
يجب ألا يُرجع هذا الأمر أي اختلاف إطلاقاً في المسارات المذكورة أعلاه.

---

## ٣. بروتوكول الاختبار السلبي الإلزامي (Negative Testing)
كل إصلاح لعيب برمجي (bug fix) أو ميزة جديدة يجب أن يصحبه اختبار سلبي:
1. **يفشل على الكود القديم** (`origin/main`).
2. **ينجح على كود الفرع الجديد** (`HEAD`).

**أوامر التحقق التجريبية للمراجع**:
```bash
# الخطوة أ: استرجاع كود المصدر القديم مع إبقاء ملفات الاختبار الجديدة
git checkout origin/main -- src/
python -m pytest -q tests/test_<new_feature>.py
# النتيجة المتوقعة الحتمية: FAIL (فشل الاختبار يؤكد أنه يقيس المشكلة الحقيقية)

# الخطوة ب: استعادة كود المصدر المحدث في الفرع
git checkout HEAD -- src/
python -m pytest -q tests/test_<new_feature>.py
# النتيجة المتوقعة الحتمية: PASS (نجاح الاختبار يثبت فاعلية الإصلاح)
```
إذا نجح الاختبار على كود `main` القديم، فهو اختبار شكلي غير صالح ويُرفض طلب السحب فوراً.

---

## ٤. فحص حزمة الفرع (Branch Package Gate)
التحقق من اكتمال مجلد الحزمة في `docs/branches/<branch-name>/`:
- `HANDOFF.md`: بالعربية، ≤ ٨٠ سطراً، يتضمن ماذا ولماذا، الملفات، أوامر الاستخدام الحقيقية، كيف تتحقق، والمخاطر، وهوية الوكيلين.
- `SKILLS.md`: بيان المهارات المستخدمة ومساراتها ومصادرها.
- `usage.html`: إنفوجرافيك 1600×900 بكسل، RTL، نص عربي خارج كتل الكود، بلا صور مولدة وبلا مكتبات خارجية (CDN).
- `usage.png`: لقطة شاشة مولدة عبر Playwright بمقاس 1600×900 تماماً، والنصوص غير مقصوصة والحروف العربية سليمة وغير معكوسة.

---

## ٥. فحص قواعد المنتج والصياغة (Product & Wording Rules)
- **منع النسب المئوية**: لا تستخدم رمز النسبة المئوية % أو ٪؛ الأرقام أعداد فقط.
- **منع ادعاء الدقة**: أي رقم يُذكر في توثيق أو واجهة يجب أن تتبعه عبارة: «أعداد توجيه وليست دقة».
- **منع ادعاء السبق**: منع استخدام كلمة «الأول» للسبق؛ والصيغة المعتمدة: «في حدود بحثنا لم نجد...».
- **صيغة التدريب**: الالتزام بصيغة «لم ندرّب نموذجاً بعد»؛ ويُمنع نهائياً لفظ «درّبنا».
- **حوكمة اللجنة**: «وكيلان» (وليس ثلاثة) بعتبة 85 للفاحص الحتمي.
- **لا اعتماد آلي**: كلمة «اعتماد» محجوزة حصراً للمتخصص البشري.
- **لا مفاتيح في ملف أو شات**: المفاتيح عبر متغيرات البيئة فقط (`LLM_API_KEY`, `LLM_BASE_URL`).
- **عدم اختلاق أي نص مصدري**: لا يُسمح بتأليف أو اختلاق أي نص قرآني أو تفسيري حتى في النماذج التجريبية (Mockups/Tests)؛ كل نص مقتبس يجب أن يطابق نصاً حقيقياً في `data/**/spans` حرفاً بحرف.
- **منع أسماء الأشخاص**: خلو الكود والوثائق وملاحظات السحب من أسماء أي أشخاص.

---

## ٦. صيغة تقرير المراجعة (Review Verdict Template)

يُخرج المراجع تقريره بالصيغة المحددة أدناه مصنفاً الملاحظات بحسب خطورتها:
- **P0 (حرج / يمنع الدمج - Blocking)**: خرق قواعد المنتج، مساس بالبيانات المثبتة، غياب الاختبار السلبي، كشف أسرار، أو فشل CI.
- **P1 (هام / يُصلح قبل الدمج)**: نقص في حزمة الفرع، مخالفة لمعايير الوصول WCAG 2.2 AA، تداخل نصوص في usage.png.
- **P2 (تحسين / ثانوي)**: تنسيق تعليقات، توضيح لغوي طفيف.

```markdown
### نتيجة مراجعة طلب السحب: [PASS / BLOCK]

- **المنفّذ**: [اسم الوكيل/النموذج]
- **المراجع المستقل**: [اسم الوكيل/النموذج]

#### الملاحظات المصنفة:
- [P0/P1/P2] [المسار:رقم_السطر]: وصف الملاحظة الدقيق وسبب المخالفة وكيفية تصحيحها.

#### بوابات التحقق:
- [ ] سلامة البيانات المثبتة (`git diff origin/main -- data/` فارغ).
- [ ] الاختبار السلبي (فشل على main ونجح على الفرع).
- [ ] حزمة الفرع الأربعة مكتملة و`usage.png` بمقاس 1600×900 سليم.
- [ ] قواعد الصياغة والأمان مطبقة بالكامل.

**الحكم النهائي**: [PASS / BLOCK]
```
