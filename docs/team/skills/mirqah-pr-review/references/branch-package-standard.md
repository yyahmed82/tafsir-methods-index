# معيار حزمة الفرع — مِرْقاة

كل فرع يُفتح له PR يحمل الحزمة نفسها. لا يُدمج PR بدونها.

## مكان الحزمة
`docs/branches/<اسم-الفرع-بشرطات>/` — مثال: `docs/branches/build-grounding-contract/`

## الملفات الأربعة

| الملف | المحتوى |
|---|---|
| `HANDOFF.md` | بالعربية، ≤ ٨٠ سطراً: ١) ماذا تغيّر ولماذا (سطران) ٢) الملفات المتغيرة ٣) **طريقة الاستخدام** خطوة بخطوة بأوامر حقيقية منسوخة من `--help` ٤) كيف تتحقق بنفسك (الأوامر + النتيجة المتوقعة) ٥) ما لم يُنجز / مخاطر ٦) من نفّذ ومن راجع (اسم الوكيل والنموذج الفعلي) |
| `SKILLS.md` | المهارات والأدوات المستخدمة في الفرع، ولكل واحدة: لماذا، وأين ملفها (`docs/team/skills/...` أو مصدر خارجي مع الرابط) |
| `usage.html` | إنفوجرافيك «طريقة الاستخدام» صفحة واحدة 1600×900، RTL، بالهوية نفسها في كل الفروع: خلفية فاتحة، خط النظام العربي، ٣–٦ خطوات مرقّمة، أوامر/أزرار حقيقية، شريط سفلي: اسم الفرع + «مِرْقاة · فهرس مناهج التفسير». بلا صور مولّدة، بلا CDN، بلا أسماء أشخاص |
| `usage.png` | لقطة `usage.html` بـ Playwright (1600×900) — هي ما يُعرض في PR |

## المرجعية العالمية (نفس المراجع في كل فرع)

| المجال | المعيار |
|---|---|
| الوصول | **WCAG 2.2 AA**: تباين ≥ 4.5:1، تركيز ظاهر، أهداف لمس ≥ 24px، بلا اعتماد على اللون وحده |
| واجهات الويب | **Vercel Web Interface Guidelines** (`briefs/web-interface-guidelines.md`) |
| RTL | `dir="rtl"` + خصائص منطقية (`margin-inline`…)، الأرقام والأوامر اللاتينية داخل `<bdi>`/`dir="ltr"` |
| التوثيق | **Diátaxis**: HANDOFF = دليل كيفية (how-to) + مرجع مختصر؛ لا خلط بين الشرح والمرجع |
| الرسائل | **Conventional Commits** (`feat(scope):`, `fix(scope):`, `docs(scope):`) |
| الاختبار | كل إصلاح = اختبار سلبي **يفشل على main وينجح على الفرع** (يُثبته المنسّق، لا المنفّذ) |
| المراجعة | منفّذ ومراجع من **شركتين مختلفتين**، مراجعة عمياء عدائية، والحكم PASS/BLOCK |

## الإنفوجرافيك المفصّل (usage.html)
- **٥–٧ خطوات** مرقّمة، كل خطوة: العنوان، لماذا، الأمر أو الزر الحقيقي، **الناتج المتوقع** (سطر من مخرج فعلي)، وعلامة «توقّف هنا إن…».
- شريط «ما لا يفعله هذا الفرع» (حدود النطاق).
- شريط «كيف تعرف أنه يعمل» (أمر تحقق واحد + ناتجه).
- النص العربي **خارج** كتل الكود دائماً (الكود monospace يكسر تشكيل العربية).
- كلمة «اعتماد» محجوزة للمتخصص البشري.

## بوابات الحزمة (يشغّلها المنفّذ، ويتحقق منها المراجع)
1. كل أمر في `HANDOFF.md` و`usage.html` موجود فعلاً (`--help` أو ملف حقيقي).
2. `usage.png` موجود ومقاسه 1600×900، والنص العربي غير معكوس.
3. قواعد الصياغة: لا «الأول» للسبق، لا %، لا ادعاء دقة، «لم ندرّب»، «وكيلان»، «أعداد توجيه وليست دقة».
4. لا تعديل على `data/**`.

## بوابة تجربة المستخدم (لأي فرع يلمس `web/` أو `src/*template*`)
- مراجعة مقابل Web Interface Guidelines (`briefs/web-interface-guidelines.md`) — نتائج `file:line`.
- مراجعة تصميم (مهارة frontend-design): التسلسل البصري، المسافات، الحالة الداكنة، الجوال 375px، التباين ≥ 4.5:1، التركيز بلوحة المفاتيح، RTL.
- لقطات قبل/بعد في `docs/branches/<branch>/shots/`.
- لا PR قبل إغلاق كل ملاحظة P0/P1.

## نص PR (القالب)
```
## ماذا ولماذا
## الحزمة: docs/branches/<branch>/ (HANDOFF · SKILLS · usage.png)
## التحقق: pytest · selftest · اختبارات سلبية تفشل على main وتنجح هنا
## المراجعة المستقلة: <الوكيل/النموذج> — PASS
## ممنوعات: لا data/** · لا اعتماد آلي · لا مفاتيح
```
